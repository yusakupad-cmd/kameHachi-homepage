# docs/strategy — 戦略・要件の置き場

## ここは何か

**Claude が書き、Codex が読む**ためのディレクトリ。「なぜやるか」「何を作るか」「どうなったら成功か」を置く。
実装コードは置かない。逆に、ここに書かれていない仕様を Codex が勝手に決めることもしない。

## 3ファイル体制における位置づけ

| ファイル | 寿命 | 書く人 | 内容 |
|---|---|---|---|
| `AGENTS.md` | 長い（月単位） | 人間＋Claude | 変わらないルール。禁止事項・技術制約・テストゲート |
| `docs/strategy/*.md` | 中（案件単位・**追記型**） | **Claude** | なぜ・何を・成功条件。日付順に積む |
| `HANDOFF.md` | 短い（タスク単位・**上書き**） | Claude / Codex | 現在地・次の1手・完了条件・触らないこと |

`CLAUDE.md` は `@AGENTS.md` の1行のみ。規約を二重管理しない。

## 命名規則

```
YYYY-MM-DD_内容_v1.md
例) 2026-08-18_リサーチコックピット_要件定義_v1.md
```

古いものは消さずに残す。判断の経緯が後から追えることに価値がある。

## 依頼の定型文

**Claude へ**
> `~/projects/kameHachi-homepage` を読んで。結論は `docs/strategy/YYYY-MM-DD_<内容>_v1.md` に書いて。
> **実装はしない。** 最後に `HANDOFF.md` を更新して。

**Codex へ**
> `AGENTS.md` と `HANDOFF.md` と `docs/strategy/<該当ファイル>` を読んでから着手して。
> 完了したら `HANDOFF.md` を更新して。
